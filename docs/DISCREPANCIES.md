# 디자인 산출물 ↔ 데이터 불일치

구현 전에 정리해야 할 항목. 발견 시점: 목 데이터 작성 중.

## 1. DECREE 37/2026의 영향 제품 수 — S2와 S3가 어긋난다

| 위치 | 표기 |
|---|---|
| S2 Laws 목록 | `제품 4` |
| S3 Law Detail | `AFFECTED — 3` |

**판단: 4가 맞다.** 라벨 표시 규정은 사전포장 식품 전 품목에 적용되므로 유자청(HS 2007.99)도 해당된다. 제외할 근거가 없다.

**조치**: `seed/data/laws.json`의 `VN-2026-037.affectedProductIds`를 4개로 확정했다.
구현 시 **S3의 섹션 라벨을 `AFFECTED — 4`로 고치고 제품 행을 4개로** 만든다. 유자청은 `impact: "low"`.

이 수치는 하드코딩하지 말고 `law.affectedProductIds.length`에서 뽑는다. 그러면 같은 종류의 어긋남이 다시 생기지 않는다.

## 2. CIRCULAR 29/2023은 제품 3개가 맞다

영양성분 표시 의무는 사전포장 가공식품 대상이고, 유자청은 단순 과실 가공품으로 제외했다. S2 표기 `제품 3`과 일치한다. **조치 없음.**

## 3. 지오그래피 렌더링 미확인

`design/neo-dots.js`는 Claude Design 런타임에서 실행된다. 로컬 정적 렌더에서는 캔버스가 비어 나온다.
S1 지구본과 S5 지도의 실제 렌더 결과를 캔버스에서 확인하지 못했다. 포팅(build-plan §10 8단계) 시 시각 결과를 처음으로 검증하게 된다.

## 4. 모든 수치는 파생값으로

디자인에 박혀 있는 숫자들 — `대응 필요 3건`, `MUST DO — 4`, `PRIORITIES — 3`, `PRODUCTS — 4`, `읽지 않음 3`, `규제 5 · 미완 액션 10` — 은 **전부 데이터에서 계산**한다. 문자열로 박으면 localStorage 상태가 바뀔 때 즉시 거짓말이 된다.

`규제 5 · 미완 액션 10` 검산: 법률 5건, 전체 액션 9건. **10이 아니라 9다.**
→ 이것도 파생값으로 처리하면 자동으로 맞는다.

# 판정 — 4단계 완료 시점 (S1 Home)

Claude Code가 올린 7건과 판단 3건에 대한 확정. **이 판정이 계획서보다 우선한다.**

## 판단 3건 — 전부 승인

**shadcn init 되돌림.** 옳다. `--accent: oklch(0.97 0 0)`가 들어왔다면 시안이 흰색이 되어 전 화면이 무너졌다. `--radius: 0.625rem`는 규칙 2 위반이고, 흰 배경 `@layer base`와 `.dark` 블록은 단일 테마 결정과 충돌한다.

**단, 9단계 Drawer는 `npx shadcn add drawer`로 받지 말 것.** 같은 오염이 재발한다. `npm i vaul` 후 래퍼를 직접 쓴다. 40줄이면 되고, `border-radius: 0`을 강제해야 하므로 어차피 손을 봐야 한다.

**Pretendard 자체 호스팅.** 옳다. 400/500/700만 쓰는데 가변폰트 2.06MB는 낭비다.

**Next.js 16 + Turbopack.** 11단계에서 Serwist를 시도하지 말고 **서비스워커를 직접 쓴다.** 우리가 필요한 건 정적 자산 precache와 JSON 7개 + geo 1개의 stale-while-revalidate뿐이다. 60줄이면 끝나고 번들러에 묶이지 않는다. Serwist를 넣으면 Turbopack 호환성 문제를 떠안는 대가로 쓰지도 않을 기능을 받는다. 단순함이 먼저다.

## 7건 판정

**1. S2 행 92px — 승인.** `--row-law: 92px` 유지. 계획서의 3종이 틀렸고 원본이 맞다.

**2. 탭바 가운데 정렬 — 승인.** 규칙 문구를 고친다: *"화면 콘텐츠는 전부 좌측 정렬. 탭바와 시트 드래그 핸들은 예외."*

**3. 상태 스트립 gap:12 — 반려. 14로 정규화한다.**
원본이 진실이라는 원칙의 예외다. 2px 차이는 아무도 지각하지 못하는데 매직 넘버는 영구히 남는다. 의도된 값이라는 근거가 없고, 나머지 모든 행이 14다. 시스템 무결성이 이긴다.

**4. 액션 문구는 데이터를 따른다 — 승인.**
S1↔S3가 같은 레코드를 가리켜야 6단계 공유 스토어가 성립한다. 문구 통일은 필수다.

**추가 확인 필요**: 데이터 문구가 원본보다 길다. 390px에서 `--row-action: 66px` 안에 한 줄로 들어가는지 렌더로 확인할 것. 넘치면 데이터 문구를 줄인다 — 데이터는 우리 것이고 행 높이는 원본 값이다.

**5. S6 EARLIER 날짜 — 승인.** 기준일보다 미래인 날짜는 원본 오기다. 데이터가 맞다.

**6. 체크박스 체크 상태 `--accent` 채움 + `--on-color` ✓ — 승인.**
원본이 박스 안에 `700 10px/1 · color:#171717`을 예약해둔 것은 색면 채움의 명백한 증거다. 근거가 좋다.

시안을 쓴 것도 맞다. 이 앱의 긍정·활성 계열은 시안 하나다 — 활성 탭, 링크, `施` 마커, CTA가 전부 시안이다. 체크박스가 여기 합류하는 게 자연스럽다. 초록 `--risk-low`는 S6 '액션 완료' 알림 유형 전용으로 남긴다. 둘을 섞으면 의미가 흐려진다.

**7. D-Day 배지 색 경계 — 30일 단일 컷을 3단으로 교체한다.**

원본의 확정점은 둘이다. D-14 = critical, D-45 = medium. 30일 컷은 두 점을 만족시키지만 `--risk-high`를 D-Day에서 영영 쓰지 않게 만든다.

```
기한 경과 또는 D-14 이하  →  --risk-critical
D-15 ~ D-30              →  --risk-high
D-31 이상                →  --risk-medium
deadline === null        →  배지 없음
```

두 확정점을 그대로 통과하고 4색 중 3색을 쓴다. 초록은 D-Day에 쓰지 않는다 — 마감일 배지가 "안전"으로 읽히면 안 된다. `DECREE 15/2018`처럼 `deadline`이 없으면 배지 자체를 그리지 않는다(원본과 일치).

## 새로 발견된 것 — 한자 마커의 플랫폼 편차

**施 留 豫가 Pretendard 서브셋에 없다**는 확인은 중요하다. serif 폴백이 실제로 동작한다는 뜻이지만, **어느 serif로 떨어질지는 기기마다 다르다.** Windows는 바탕, macOS·iOS는 다른 명조, Android는 또 다르다. 이 앱의 서명 요소가 기기마다 다른 골격으로 찍힌다.

**조치: Noto Serif KR에서 이 세 글자만 서브셋해 자체 호스팅한다.** 3글자면 2~4KB다.

```css
@font-face {
  font-family: 'NEO Mark';
  src: url('/fonts/neo-mark-subset.woff2') format('woff2');
  unicode-range: U+65BD, U+7559, U+8C6B;  /* 施 留 豫 */
  font-display: block;
}
.t-mark { font: 700 12px/1 'NEO Mark', Pretendard, serif; }
```

`font-display: block`을 쓰는 이유 — 마커가 폴백으로 잠깐 찍혔다가 바뀌면 눈에 띈다. 3글자짜리 파일이라 로드는 즉시다.

# 7단계에서 발견 — S4·S6 아트보드 ↔ 데이터

아트보드가 목 데이터보다 먼저 만들어져 숫자가 어긋나 있다.
§4의 원칙대로 **전부 데이터에서 계산**하고 아트보드 숫자는 버린다.

## 5. S4 우선순위 타일 수치

| 타일 | 아트보드 | 데이터 파생 |
|---|---|---|
| 라벨링·표시 | 법률 3 · 미완 5 | **법률 2 · 미완 6** |
| 식품안전·인증 | 법률 2 · 미완 2 | **법률 2 · 미완 0** |
| 포장·환경 | 법률 1 · 미완 3 | 법률 1 · 미완 3 (일치) |

법률 수는 `law.category` 매칭, 미완은 그 법률들의 미완 액션 합이다.
labeling = VN-2026-037(액션 4) + VN-2023-029(액션 2) = 법률 2 · 미완 6.
safety = VN-2026-046 + VN-2018-015, 둘 다 액션이 없어 미완 0.

**위험도는 아트보드와 일치한다** — HIGH / MEDIUM / CRITICAL.
해당 category 법률 중 최대 위험도이고, 라벨과 상단 4px 바가 같이 이 값을 쓴다.

| 제품 | 아트보드 | 데이터 파생 |

| 김치양념 소스 | 법률 3 | **법률 5** |
| 조미김 | 법률 3 | **법률 5** |
| 고추장 | 법률 2 | **법률 5** |
| 유자청 | 법률 1 | **법률 4** |

그 제품을 `affectedProductIds`에 포함하는 법률 수다. 법률 5건 중 4건이
제품 4종 전부를 담고 있고, CIRCULAR 29/2023만 유자청을 뺐다(§2 참조).
그래서 5/5/5/4가 된다.

## 7. S6 n-05 유형 색

법률 위험도를 따른 것도 아니다: n-05의 법률 DECREE 15/2018은 LOW(#22C55E)라
어느 규칙으로도 #E0A800이 나오지 않는다.

## 8. S6 EARLIER 날짜 (4단계에서 이미 확인)

아트보드 `09.28` / `09.21`은 기준일(2026-09-03)보다 미래라 성립하지 않는다.

# 9단계 판정 — S5 Map

아트보드가 목 데이터보다 먼저 그려져 어긋난 지점, 그리고 명세가 비워둔 자리를 여기서 닫는다.

## 9. 점 색 — S1과 S5가 다르다

8단계에서 `DotGeo`의 `dotColor` 기본값을 `--text-3`로 두고 남겨둔 질문이다.
**S5는 `dotColor="var(--geo-dot)"`를 넘긴다. `DotGeo`의 기본값은 건드리지 않는다.**

S1 지구본은 전경 히어로라 `--text-3`(#6B6B6B)로 또렷해야 하고, S5 지도는 시트 뒤에
깔리는 배경이라 `--geo-dot`(#3A3A3A)로 물러나야 한다. 아트보드도 S5에만
`dot-color="#3A3A3A"`를 넘기고 S1에는 넘기지 않는다.

## 10. 지도는 전체화면 배경이 아니다

design-prompts §S5의 "전체화면 SVG 점지도"는 아트보드와 어긋난다. 아트보드는 330×366 박스를
`top:60px; right:-36px`으로 우측 밖으로 흘린다 — S1 지구본과 정확히 같은 어법이다.
같은 문서가 "S1처럼 우측 밖으로 흘려 좌측에 여백을 남긴다"고도 적었으니, "전체화면"이 헐거운 말이다.

`Screen`이 상단 44px을 이미 잡으므로 콘텐츠 좌표로 환산해 `top:16px; right:-36px`이 된다.
실측: 지도 좌측에 96px 여백이 남고 우측 36px이 프레임 밖으로 잘려 나간다.
**가운데 정렬하지 않는다. 비대칭이 의도다.**

## 11. 시트 높이는 320px이 아니라 418px

design-prompts는 "높이 320px", 아트보드는 418px이라 적었다. **둘 다 맞다** — 탭바
(64 + 하단 34 + 경계선 1 = 99px)가 시트 위에 떠서 아래를 덮으므로 보이는 높이가 319px이 된다.
"320px"은 탭바 하나선을 경계로 세는 어림값이다.

z-index는 **지도 기본 / 상단바 3 / 시트 4 / 탭바 5**.

시트 내용은 정확히 317px(핸들 9 + 10 + H1 30 + 10 + Meta 18 + 20 + 행 186 + 12 + 링크 22)이라
시트 안쪽 417px에 남는다. **시트를 스크롤 컨테이너로 만들지 않는다** — `overflow`는 `visible`이고
`scrollHeight === clientHeight`다.

## 12. 국가 위험도는 파생값 — VN은 HIGH가 아니라 CRITICAL

아트보드의 `HIGH`(#FF8A00)는 목 데이터보다 먼저 그려진 값이라 버린다.

국가 위험도는 **그 국가 법률의 최대 위험도**다 — §5의 S4 우선순위 타일과 같은 규칙이고,
`derive.ts`의 `maxRisk()` 하나를 둘이 같이 쓴다. VN은 `DECREE 110/2026`이 critical이므로
**CRITICAL(#FF3B30)**이다.

시트 H1 옆 배지와 지도 위 VN 마커 라벨이 같이 이 값을 본다 — 마커 문구가 `VN · CRITICAL`이 되는
이유다. 나머지 국가는 `company.json`의 `active: false`를 읽어 `ID · 곧 지원` / `TH · 곧 지원`이고,
KR만 출발지라 데이터에 없어 `KR · 출발` 상수다.

## 13. 시트 3행의 선정 규칙

아트보드의 3건(37 · 110 · 46)도 데이터 이전 값이라 버린다. `DECREE 46/2026`은 보류라 액션이 없어
"할 일"이 하나도 없는데 시트에 올라와 있다.

**규칙: 미완 액션이 있는 법률을 마감 임박순으로 정렬해 상위 3건.**

| 아트보드 | 데이터 파생 |
|---|---|
| DECREE 37/2026 · D-45 | **CIRCULAR 29/2023 · 기한 경과** |
| DECREE 110/2026 · D-14 | **DECREE 110/2026 · D-14** |
| DECREE 46/2026 · 보류 | **DECREE 37/2026 · D-45** |

액션이 없는 보류(46)와 휴면(15/2018)은 여기서 빠지고, 아래 링크 "법률 5건 모두 보기"가 전부를 받는다.
액션을 전부 체크해 0건이 되면 행 대신 Meta 한 줄 **"대응이 필요한 법률이 없습니다"**만 남는다.

행 수·건수·링크 문구는 전부 파생값이다. 문자열로 박지 않는다 — 아트보드의 `미완 액션 10`도
실제로는 **9**(액션 총 9건)다.

## 14. vaul을 설치하지 않는다

드래그로 펼친 뒤의 상태가 어느 문서에도 없고, 시트 내용이 418px에 정확히 맞아 확장할 것이 없다.
36×3 `--text-3` 핸들은 **시각 요소로만** 둔다 — 이 화면의 유일한 중앙 정렬이다(탭바와 함께
§4 좌측 정렬 규칙의 명시된 예외 둘).

검색과 "필터"도 아트보드가 `span`이라 비기능으로 둔다. 지원 국가가 VN 하나뿐이어서 검색이 할 일이
없다. `cursor:pointer`를 주지 않는다 — 아트보드의 "필터"에는 `cursor:pointer`가 붙어 있지만,
누를 수 없는 것에 누를 수 있다고 말하지 않는다.

검색 행의 하나선은 좌우 20px 안쪽으로 물러난다(바깥 `padding:0 20px`, 안쪽에 `border-bottom`).
아트보드 S5와 S2가 구조까지 같으므로 5단계의 S2 구현을 그대로 따랐다.

## 그 밖에 — `DotGeo`에 `onProject`를 되살렸다

원본 `neo-dots.js`는 `'neo-ready'` 이벤트로 projection을 밖에 넘겼고, 8단계 포팅에서 그 통로가
빠졌다. 마커를 점 위에 얹으려면 같은 투영이 필요하므로 선택 prop으로 되돌렸다.

콜백은 **ref로 받고 `useEffect` deps에 넣지 않는다.** 넣으면 인라인 함수를 넘긴 호출부에서
렌더마다 지도를 새로 만들고, 마커 좌표 `setState`까지 얽혀 순환한다.

# 10단계 판정 — 상태 화면

계획서 §8의 표는 "로딩 | 모든 목록", "에러 | 데이터 실패"라고 적었다. 이 앱의 데이터 경로를
보면 둘 다 존재하지 않는 상태다. 표를 그대로 옮기면 없는 지연을 만들어야 한다.

## 15. 목록 스켈레톤을 만들지 않는다

`data/*.json`은 `lib/data.ts`가 정적으로 임포트해 번들 안에 들어 있다. fetch가 없고 await가
없다. 목록이 "로딩 중"인 순간이 존재하지 않는다.

스켈레톤을 보여주려면 인위적 지연을 넣어야 하는데, 그건 사용자에게 없는 기다림을 만들어
보이는 것이다. **계획서 §8의 "로딩 | 모든 목록"을 폐기한다.**

앱에서 실제로 비동기인 것은 `/geo/land-110m.json` 하나뿐이다(`lib/geo.ts`).
그래서 스켈레톤도 `DotGeo` 자리에만 있다.

## 16. 데이터 에러 화면도 목록에 붙이지 않는다

같은 이유다. 목록이 실패할 경로가 없다. 에러는 두 곳에만 만든다.

| 자리 | 받는 것 | 문구 |
|---|---|---|
| `app/error.tsx` | 렌더 중 던져진 예외 | Body "규제 데이터를 불러오지 못했습니다" + "다시 시도" → `reset()` |
| `DotGeo` | land 로드 실패 | Meta "지도를 불러오지 못했습니다" + "다시 시도" → 재요청 |

`lib/geo.ts`가 실패 시 `landPromise`를 null로 비우므로 재시도가 실제로 새 요청을 낸다.
차단 → 에러 → 차단 해제 → "다시 시도"에서 `200 OK` 한 건이 나가고 지도가 그려지는 것을 확인했다.

## 17. `app/not-found.tsx` — 계획서에 없지만 열려 있던 구멍

`app/laws/[id]/page.tsx`가 `notFound()`를 부르는데 받는 화면이 없었다. Next 기본 화면은 흰
배경이라 단일 다크 테마가 그 순간 깨졌다. 계획서 §8에 없지만 에러 계열의 일부로 여기서 닫는다.

H1 "없는 법률입니다." + Meta 한 줄 + `--accent` 밑줄 "법률 목록으로". HTTP 상태는 404다.
**탭바를 두지 않는다** — 돌아가는 길 하나만 있는 모달성 화면이다. `app/error.tsx`도 같다.

## 18. S4 빈 상태는 도달하기 어렵다

`usePriorities`에 제거 기능이 없다(디자인에 없는 한 방향 동작). 기본값이 3건이라 0으로
내려갈 길은 `neo.priorities`에 빈 배열이 저장된 경우뿐이다. 그래도 만든다 — 타일 격자만
남고 아무 말이 없으면 무엇을 해야 하는지 알 수 없다.

`+ 영역 추가` 타일은 그대로 두고 그 아래에 Meta 한 줄만 얹는다.

## 19. 오프라인 바는 `Screen`이 렌더한다

여섯 화면이 전부 `Screen`을 쓰므로 한 곳만 고치면 된다. `Screen`에 `'use client'`가 붙는다 —
페이지들은 이미 전부 클라이언트다.

`getServerSnapshot`은 언제나 `true`(온라인)를 돌려준다. 서버는 `navigator`를 모르므로 서버에서
오프라인이라고 그려 두면 하이드레이션 불일치가 난다. 오프라인으로 시작한 경우에도 하이드레이션
직후 스냅샷 검사에서 바가 뜬다 — 첫 페인트에 한 프레임 늦는 대신 경고를 만들지 않는다.
확인: 여섯 라우트의 SSR HTML에 `role="status"`가 0건이고 콘솔 경고도 0건이다.

바가 켜지면 스크롤 영역 `top`을 `44px` → `calc(44px + var(--badge-h))`로 민다. 값을 두 번
적지 않으려고 `44 + 22`를 쓰지 않았다. 겹쳐서 상단바를 가리지 않는다.

**알려진 부작용**: S5 지도 박스는 아래 끝이 시트 상단(426px)과 정확히 맞닿아 있어서, 22px
밀리면 아래 22px이 시트 뒤로 들어간다. 그 띠에 있는 것은 육지 점의 1.27%(자바 남단)뿐이고
마커 4개(가장 낮은 ID가 y 312)와 항로는 전부 위에 있다. 오프라인 바 자체가 가리는 것은
아무것도 없다. S5만 예외 처리하는 것보다 이쪽이 낫다고 봤다 — "한 곳만 고친다"를 깨지 않는다.

서비스워커와 실제 캐시는 11단계다. 여기서는 연결 여부만 본다.

## 20. 스켈레톤은 `DotGeo` 안에서 처리한다

호출부(S1·S5) 두 곳이 같은 `loading | ready | error` 분기를 반복할 이유가 없다.
캔버스 위에 겹치고, 상태는 컴포넌트가 혼자 안다.

- **250ms 게이트.** `lib/geo.ts`가 모듈 레벨 Promise로 캐싱하므로 두 번째 마운트부터 즉시
  끝난다. 게이트가 없으면 그때마다 블록이 한 프레임 깜빡인다. 확인: 캐시된 뒤 /laws ↔ /map을
  왕복해도 `.neo-pulse`가 한 번도 나타나지 않았다(MutationObserver).
- **shimmer 금지.** `@keyframes neo-pulse`는 `opacity`만 건드린다(1 ↔ .45, 1.6s ease-in-out).
  실측에서 `background-image: none` · `transform: none` · `filter: none`을 확인했다 —
  좌→우 광택을 만들 기제가 아예 없다.
- **`prefers-reduced-motion: reduce`에서 `animation: none`.** 블록은 남긴다 — 자리를 비우면
  무엇을 기다리는지 알 수 없다.
- `aria-hidden="true"`를 host div에서 캔버스로 내렸다. 에러 문구와 "다시 시도"가 읽혀야 한다.

## 그 밖에

`EmptyState`에 `size`(`'body' | 'meta'`) 하나를 뒀다. 계획서는 S2 목록 자리를 Body로,
판정 4는 S4를 Meta로 적었고 둘 다 맞다 — 목록을 대신하는 문구와 타일에 붙는 곁말은 위계가
다르다. 빈 상태 문구 색은 전부 `--text-3`으로 맞췄다(9단계 S5의 빈 줄과 같다).

오프라인 바 문구에 `tnum`을 넣었다. 시각 문자열이고, 앱의 다른 시각 표시가 전부 그렇다.

`button`의 UA 기본 `text-align: center`를 `EmptyState` 액션에서 `left`로 덮었다. 줄어든
폭이라 눈에 보이는 차이는 없지만 §4 좌측 정렬 전수 검사를 통과해야 한다.

# 11단계 판정 — PWA

계획서 §9는 Serwist + `data/*.json` stale-while-revalidate + Lighthouse PWA 통과로 적혀 있다.
세 가지 모두 이 앱에서는 성립하지 않는다.

## 21. `data/*.json`은 캐싱 대상이 아니다

lib/data.ts가 정적으로 임포트해 JS 청크 안에 들어 있고 독립된 URL이 없다.
없는 URL에 stale-while-revalidate를 걸 수 없다 — 10단계 판정 15와 같은 이유다.

런타임 캐싱 대상은 **실제로 URL을 갖는 것뿐**이다.

| 대상 | 전략 |
|---|---|
| 문서(내비게이션) · RSC 페이로드 | network-first → 캐시 폴백 |
| `/_next/static/*` · `/fonts/*` · `/geo/*` · `/icons/*` · 매니페스트 · 파비콘 | cache-first |
| 그 밖 | 손대지 않고 통과 |

빌드 산출물 프리캐시 매니페스트도 만들지 않는다. 해시 파일명을 알려면 빌드 훅이 필요한데
`/_next/static/*`은 해시가 붙어 불변이므로 cache-first 런타임 캐싱으로 충분하다.
install에서는 URL이 고정된 13개만 받는다.

## 22. 프리캐시할 라우트는 앱이 서비스워커에 알려준다

public/sw.js는 정적 파일이라 data/laws.json을 임포트할 수 없다. 법률 5건의 id를 거기 박으면
파생값 원칙이 깨진다. `components/ServiceWorker.tsx`가 `lib/data`의 laws에서 URL을 만들어
postMessage로 넘기고 SW가 받아 캐시한다. 법률이 늘면 목록도 같이 는다.

**개수는 10개다** (판정 문서의 "11개"는 셈이 틀렸다). 6화면 중 S3는 URL이 아니므로
정적 라우트는 5개(`/` `/laws` `/company` `/map` `/notifications`)이고 법률 상세 5건을 더해 10이다.
코드가 `laws`에서 계산하므로 숫자를 박은 곳은 없다.

## 23. 문서와 RSC는 다른 캐시에 담는다

클라이언트 내비게이션은 문서가 아니라 RSC 페이로드(`?_rsc=<해시>`)를 받는다.
해시가 빌드마다 바뀌므로 URL 완전 일치로는 찾을 수 없어 **키를 쿼리 없는 경로로 정규화**한다.

한 캐시에 담고 `ignoreSearch`로 찾는 것은 안 된다 — `/laws` 문서와 `/laws?_rsc=…` 페이로드가
서로를 물어 오고, 라우터가 HTML을 flight 페이로드로 파싱하려 든다. 그래서 캐시를 둘로 나눈다
(`neo-v1` / `neo-v1-rsc`).

**RSC 페이로드도 프리캐시한다.** 처음에는 문서만 담았는데, 오프라인에서 탭을 누르면 아무 일도
일어나지 않았다 — RSC 요청이 실패하고 라우터가 하드 내비게이션으로 떨어지지도 않고 그냥 멈춘다.
해시를 몰라도 받을 수 있다: `RSC: 1` 헤더로 요청하면 Next 16이 `<경로>?_rsc`로 307을 주고,
그 URL이 같은 페이로드를 돌려준다(`text/x-component`). 그래서 라우트마다 문서와 RSC를 함께 담는다.
첫 방문 한 번으로 문서 10건 + RSC 10건이 결정적으로 채워진다 — Next의 링크 프리페치에 기대지 않는다.

## 24. 매니페스트는 `app/manifest.ts`로 쓴다

public/manifest.json이 아니다. 타입 검사가 붙고 layout.tsx의 metadata와 한곳에서 관리된다.
산출 URL이 `/manifest.webmanifest`(`application/manifest+json`)이므로 프리캐시 목록도 그 URL을 쓴다.

## 25. 아이콘은 앱의 서명인 施다

`var(--bg)` 바탕에 `var(--accent)` 글리프. 아이콘은 화면 콘텐츠가 아니므로 좌측 정렬 규칙을
적용하지 않고 글리프를 중앙에 둔다.

**기기 폰트에 기대지 않는다.** `public/fonts/neo-mark-65BD.woff2`를 그대로 래스터화한다 —
施가 플랫폼마다 다른 골격으로 찍히는 것을 막으려고 그 폰트를 자체 호스팅했는데, 아이콘이
시스템 명조로 찍히면 같은 문제가 홈 화면에서 되살아난다.

`scripts/make-icons.mjs`가 `@resvg/resvg-js`로 만든다. resvg의 fontdb는 woff2를 읽지 못해
("malformed font") **`wawoff2`로 압축만 풀어** 임시 ttf로 넘긴다 — 아웃라인은 손대지 않는다.
글리프 잉크 경계를 `getBBox()`로 재고 그 중심을 캔버스 중심에 맞춘다. 施는 좌우 여백이
대칭이 아니라 advance width로 놓으면 눈으로 봤을 때 가운데가 아니다.

색은 `app/globals.css`의 토큰에서 읽는다. 아이콘 스크립트에 색을 다시 적지 않는다.

크기는 192·512(any) · 512(maskable) · 180(apple-touch)이고 **maskable은 any × 0.8**이다 —
maskable 안전영역이 캔버스의 중앙 80%라서, 안전영역 대비 글리프 비율을 any의 캔버스 대비
비율과 같게 맞춘 값이다. 두 아이콘이 각자의 틀 안에서 같은 무게로 보인다.

## 26. Lighthouse PWA 통과는 검증 기준이 될 수 없다

Lighthouse 12에서 PWA 카테고리가 제거됐다. 설치 가능 조건을 직접 확인하는 것으로 대체한다.
가장 강한 신호는 **`beforeinstallprompt`가 실제로 발화하는 것**이다 — 크롬은 매니페스트
필수 항목(name/short_name·start_url·display·192/512 아이콘·maskable)과 fetch 핸들러를 가진
서비스워커가 모두 통과할 때만 이 이벤트를 쏜다. 2회차 방문에 배너가 뜬 것이 그 증거다.

## 27. 오프라인 바 문구는 REFERENCE_DATE 기준 그대로 둔다

실제 캐시 시각으로 바꾸면 기준 날짜 단일 출처 원칙이 깨진다. 실 서비스에서 `lastSync`가
생기면 그때 바꾼다. 지금 바는 연결 여부만 본다 — 캐시가 실제로 언제 채워졌는지는 모른다.

## 28. 설치 배너는 아트보드에 없다 — 기존 행 문법으로 짠다

색면으로 만들지 않는다. S6의 시안 색면("시행일 알림 켜기")과 위계가 부딪친다 —
저 블록은 놓치면 손해를 보는 것이고 이건 있으면 편한 것이다.

탭바(z-index 5) 바로 아래 `bottom: 98`에 z-index 4로 앉는다. 탭바의 상단 하나선이 위에
그려져 배너와 탭을 가르므로 보이는 높이는 63px이다. 배너가 뜨면 S1의 `scrollPadBottom`을
130 → 194로 같이 민다 — 마지막 행이 배너 뒤로 들어가면 안 된다.

2회차 방문부터 뜨고(`neo.visits`, 모듈 로드 시 한 번 증가 — 클라이언트 내비게이션으로는
늘지 않는다), "나중에"를 누르면 다시 뜨지 않는다(`neo.install.dismissed`).
`beforeinstallprompt`가 없는 브라우저에서는 아예 뜨지 않는다 — iOS Safari가 그렇고,
거기서는 공유 시트의 "홈 화면에 추가"뿐이라 우리가 대신 눌러 줄 방법이 없다.
없는 버튼을 안내 문구로 흉내내지 않는다.

## 그 밖에 — 검증에서 잡힌 것 둘

**`.gitignore`가 서비스워커를 삼키고 있었다.** `public/sw*.js`와 `public/workbox-*.js`를
무시하는 줄이 있었다. Serwist·next-pwa가 **생성하는** 산출물을 걸러내려던 규칙인데,
4단계 판정에서 서비스워커를 직접 쓰기로 했으므로 `public/sw.js`는 생성물이 아니라 소스다.
그대로 커밋하면 서비스워커가 조용히 빠진 채 배포됐을 것이다. 두 줄을 지웠다.

**버전을 올린 직후 라우트 프리캐시가 유실됐다.** 등록 직후 `controller`에게 postMessage하고
`controllerchange`를 `{ once: true }`로 듣던 구조라, 재배포 직후 로드에서는 물러나는 옛 워커에게
메시지가 가고 새 셸에는 고정 URL 13개만 남았다(라우트 10개가 비었다). `once`를 떼고 제어권이
넘어올 때마다 다시 보내도록 고쳤다 — 같은 URL을 다시 담는 것은 무해하다.
검증 8이 잡아낸 것이고, 고친 뒤 재확인해 v2 셸에 23건이 그대로 들어갔다.
