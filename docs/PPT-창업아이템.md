## 슬라이드 1 — 창업 아이템 소개

### ① 제품/기술 개요

**[좌측 박스]**

**NEO — 수출 규제 대응 실행관리 PWA**

해외 규제 원문(1차 법령)을 **자사 품목 기준 영향도**와 **실행 항목(Action)** 으로 변환하는 오프라인 우선 웹 애플리케이션. 백엔드 없는 클라이언트 전용 아키텍처(정적 JSON + localStorage).

**[우측 박스]**

도착국 4개국(VN·JP·US·ID) × 품목 3군(식품·음료 / 화장품 / 전기·전자) **12개 조합**과 국가별 공용 법령 4종을 정적 데이터셋으로 보유. 등재 법령 **61건**, 이에 연동된 실행 항목 **174건**.

사용자가 등록한 제품의 **HS 코드 상위 자릿수(hsPrefixes)** 를 법령 적용범위와 대조해 해당 법령만 선별하며, 시행일·기한·보류 여부로부터 D-Day와 위험도(4단계)를 **결정론적으로 파생**한다. 화면에 표기되는 모든 수치는 하드코딩이 아닌 파생값이다.

### ② 사용 용도

**[좌측 박스]**

**수출 실무자의 규제 대응 워크플로 도구**

대상: 해외 수출을 수행하나 전담 법무·인증 대응 조직을 갖추지 못한 국내 중소 제조·수출기업의 수출·품질 담당자.

**[우측 박스]**

사용 시나리오 — ① 출발국·도착국·품목·제품(HS 코드) 등록 → ② 홈 화면에서 **"지금 해야 할 일"** 우선순위 확인 → ③ 법령 상세에서 담당 부서·소요기간이 부여된 체크리스트 이행 → ④ 시행일·기한 도래 및 상태 변경(보류·시행 예정)을 알림으로 추적.

온보딩부터 **자사 영향 법령 1건과 그에 연동된 실행 항목 1건 도달까지 60초 이내, 최대 3탭**을 설계 기준(PRD §3 SC-1·SC-2)으로 삼는다. 통관 현장·해외 출장 등 **비접속 환경에서도 전 화면과 법령 상세 61건이 완전 동작**한다.

### ③ 아이템 목적

**[좌측 박스]**

**"법이 바뀌었다"가 아니라 "그래서 당신은 이것을 해야 한다"를 판다.**

규제 정보 열람 서비스가 아니라, **미이행 리스크의 사전 차단**을 목적으로 하는 실행관리 도구다.

**[우측 박스]**

기존 규제 정보 채널(관보·무역협회 뉴스레터·로펌 뉴스)은 조문 단위의 **정보 전달에서 종료**되며, "우리 품목에 걸리는가 / 언제까지 / 누가 무엇을 하는가"의 판정은 사용자에게 남는다. 이 판정 실패의 비용은 **통관 거부·리콜·과징금**으로 즉시 실현된다.

NEO는 그 판정 구간 — 품목 해당성 판정, 기한 산정, 부서별 과업 분해 — 을 제품이 대신 수행하여, 대응 조직이 없는 기업도 규제 이행 상태를 상시 가시화하도록 한다.

## 슬라이드 2 — 아이템 특성 및 기술성

### 중앙 원 — 핵심 명제

**규제 원문 → 실행 항목**
법령·품목·기한을 결합하는 **결정론적 변환 엔진** (`lib/derive.ts`)

### 상단 원 — 데이터 신뢰성

**검증형 정적 데이터셋 · 출처 등급 명시**

독립 출처 2건 이상 교차확인, **1차(관보·소관부처) 47건 / 2차(로펌·인증기관) 14건**을 화면에 구분 표기. 미확인 값은 추정하지 않고 공란 처리하며, 제외 법령과 그 사유까지 `DATA-SOURCES.md`에 기록. `check-data` 스크립트가 참조무결성·값 범위·HS 포함관계를 빌드 전 강제한다.

### 좌하단 원 — 판정 로직

**HS 코드 기반 적용범위 판정 · 날짜 파생 일원화**

법령의 `hsPrefixes`와 사용자 제품 HS 코드를 대조해 해당 법령만 선별(빈 배열 = 품목 무관 전면 적용). 기한 부재 시 시행 여부에 따라 `미이행` / 시행일 카운트다운으로 분기하고, 보류 법령은 배지를 생성하지 않는다. 기준일 연산은 **KST 달력일 기준 단일 진입점**(`lib/dday.ts`)으로 통일해 UTC 절삭에 의한 1일 오차를 제거했다.

### 우하단 원 — 실행 환경

**오프라인 우선 PWA · 외부 의존 0**

서비스워커를 직접 구현(Serwist·next-pwa 미사용). 프리캐시한 문서 HTML에서 `/_next/static/*` 참조를 추출해 **빌드 훅 없이 라우트별 청크와 RSC 페이로드까지 선반입**한다. 지리 데이터·폰트·아이콘을 자체 호스팅하여 **CDN 의존도 0**, 런타임 의존성 5개(next·react·react-dom·d3-geo·topojson-client). 지구본·지도는 외부 지도 라이브러리 없이 `d3-geo`로 직접 렌더링한다.

> **도형이 3개뿐이라 넣지 못한 4번째 축** — **데이터 주권**: 서버·계정·수집이 없고 기업 제품 정보는 단말 `localStorage`에만 남는다. 심사 항목에 보안·개인정보가 있다면 중앙 원 아래 캡션으로 한 줄 추가할 것.

## 작성 시 유의점

1. **"실시간 법령 수집"으로 쓰지 않는다.** 현재 데이터는 사람이 조사·교차검증한 정적 데이터셋이다(`README.md` 명시). 심사에서 자동 수집으로 오인되면 검증 요구가 들어온다. "**검증형 큐레이션 데이터셋 + 자동 무결성 검사**"가 정확한 표현이며, 실시간 연동은 로드맵 항목으로 분리한다.
2. **슬라이드 3의 청색 박스는 폭이 좁다.** 위 표의 5개 항목만 남기고 나머지는 하단 표로 분리한다.
3. **`docs/PRD-v2.md` §6의 색상 토큰(다크+시안 글로우)은 폐기된 값이다.** 현행 확정 토큰은 `app/globals.css`(중성 진회색 `#171717` 계열, 글로우·그림자 없음)다. PPT에 디자인 토큰을 인용할 경우 후자를 써야 실제 화면과 일치한다.
